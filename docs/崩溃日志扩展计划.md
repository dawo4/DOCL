# 崩溃日志扩展计划

> 1.8.0 已完成的规则、分析引擎、修复动作与界面已从本文件移除。
> 这里只保留后续尚未实施的事项；已完成能力以代码和发版记录为准。

## 一、规则运营

1. **规则命中统计**
   - 记录规则 id、置信度、是否被用户忽略，不记录日志正文、账号信息或服务器地址。
   - 默认关闭，可在设置中关闭；用于判断规则误报率和是否需要降级。
2. **规则灰度与在线回滚**
   - 远端规则带 `ruleset_version`，按比例灰度到部分客户端。
   - 新规则误报率异常时回滚上一版，不依赖发版。
3. **误报反馈闭环**
   - 当前「不是这个原因」只记在本地。
   - 后续支持导出反馈包（规则 id、版本、系统信息，不含日志正文），人工汇总后调整规则。
4. **真实崩溃样本夹具**
   - 继续补充 PCL2 / HMCL / Axolotl 的脱敏样本和本机真实崩溃报告，断言命中的规则集合。

## 二、修复能力

1. **修复影响的文件清单预览**
   - 修复计划目前只列动作，后续列出每个动作会改动、移动或删除的具体文件。
2. **修复历史与按次还原**
   - 当前只还原最近一次备份；后续保留修复历史，支持选择某一次还原。
3. **撤销新增 Mod**
   - 基于成功启动快照里的 `added` 列表，撤销前校验 SHA-256，文件已变化则拒绝删除。
4. **定点清理 `FileAlreadyExistsException`**
   - 备份后只删除日志点名的文件或目录，不动同目录其他内容。
5. **移除无效 `-javaagent`**
   - 从实例启动参数中删除指向缺失或损坏 jar 的项。
6. **损坏 jar 按 SHA-1 重下**
   - 对 `corrupted-jar`、`sha1-digest-error` 命中的文件，用 Modrinth SHA-1 反查后重新下载。
7. **更多修复类 Mod 自动安装**
   - 仅在 Modrinth 有对应项目且版本匹配时提供（如缺少 Embeddium / Indium）。
   - CurseForge 独占项目（如 JEID）保持手动，不绕过分发限制。

## 三、后续独立评估

- **AI 分析**：BYO Key 或自建端点，默认关闭，不预先排期。
- **启动前预检**：另立计划，不并入崩溃日志模块。
- **存档急救**：备份恢复、方块/实体定位，另立计划。

## 四、约束

- 任何禁用、删除、改配置都必须用户确认，执行前备份，并支持还原。
- 不自动上传日志；分享必须二次确认，并隐藏令牌与本机用户目录。
- 规则宁可少报，不可乱指；新增规则必须带夹具或明确的正则依据。
- 修复只做可逆操作；驱动、OptiFine 版本选择、存档损坏只给指引。

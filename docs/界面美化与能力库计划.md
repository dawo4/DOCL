# 界面美化与能力库计划

目标：在不破坏现有纸木设计系统的前提下提升观感与交互质量；只引入「能力型」依赖，不接完整 UI 组件库。

> 结论先行：UI 库不是美颜滤镜。当前视觉问题主要靠排版、间距、层级、动效和状态规范解决，这些零依赖；库只用来补弹层行为、语法高亮和长列表性能。

---

## 一、现状

| 项 | 现状 |
| --- | --- |
| 设计系统 | `src/styles/theme.css`（约 32 KB）、12 套内置主题 + 自定义主题编辑器 |
| 组件 | 26 个自研组件（`WoodButton` / `WoodInput` / `WoodSelect` / `WoodModal` / `WoodToggle` / `AppIcon` 等），2px 浮雕边框、无圆角 |
| 密度 | `ui_density` 三档（compact / normal / comfy），目前只影响 `.main` / `.page` / `.card-pad` 的内边距 |
| 动效 | 已有 `--dur-1/2/3` 与缓动 token、`prefers-reduced-motion` 兜底 |
| 字体 | `ui_font` 可切换字体栈；无字号阶梯 token |
| 体积（构建后） | CSS 约 260 KB；主 JS 约 578 KB；three 约 747 KB |
| 短板 | 无排版 / 间距 token；动效散落在各页面；`WoodSelect`、`WoodModal` 自绘，缺焦点陷阱与碰撞处理；config 编辑器是纯 textarea；Mod 列表靠 120 条分页而非虚拟滚动 |

---

## 二、原则

1. **视觉自持**：不引入任何会覆盖主题色的默认样式，库只补行为与能力。
2. **渐进可回滚**：每个组件、每个页面独立替换，出问题能单点退回。
3. **不牺牲首屏**：新增依赖一律动态加载，低内存模式要有降级路径。
4. **不为了美化改业务布局**：只调整样式 token、状态与交互细节。

## 三、阶段 P0：视觉打磨（零依赖）

> 纯 CSS / 模板调整，零依赖，可随时先做；不绑定版本。

### P0-1 排版 token（状态：已完成）

- [x] 在 `theme.css` 增加字号阶梯：`--text-xs / sm / base / lg / xl / 2xl / 3xl` 与 `--leading-*`
- [x] 统一页面标题、卡片标题、正文、说明文字的字号与字重，替换各页面散落的 `font-size: 11.5px` 之类硬编码
- [x] 数字类（内存、统计、版本号）统一 `font-variant-numeric: tabular-nums`
- [x] 与 `ui_font` 设置联动，切换字体后字号行高不跳变

> 实现说明：`--text-xs 10.5px` / `sm 11.5` / `base 12.5` / `lg 13.5` / `xl 17` / `2xl 22` / `3xl 27`；
> 根字号固定 14px 不跟随阶梯；`.mono`、`.display` 启用等宽数字；views / components 已统一替换。

**验收**：设置页、实例页、下载页、联机页字号层级一致；切换 12 套主题无溢出。

### P0-2 间距节奏（状态：已完成）

- [x] 增加 4px 基准间距 token：`--space-1` ~ `--space-8`
- [x] 统一卡片内边距、分组间距、表单行间距，替换散落数值
- [x] 让 compact / normal / comfy 三档真正影响间距 token，而不是只改三处 padding

> 实现说明：新增语义变量 `--space-page-y/x/bottom`、`--space-page-gap`、`--space-card-y/x`、`--space-row`、`--space-row-gap`；
> 密度只覆盖这些变量，`.main` / `.page` / `.card-pad` / `.setting` 自动跟随；compact 行距 8px、normal 12px、comfy 16px。

**验收**：三档密度切换后，设置页与实例页的行高、卡片留白明显不同且不出现挤压。

### P0-3 层级与边框（状态：已完成）

- [x] 明确三档层级：页面底 / 卡片 / 浮层，对应背景、阴影、边框强度
- [x] 统一 hover / active / disabled 三态的边框与阴影变化，收敛各页面自写的状态样式
- [x] 下拉、弹层、提示条复用同一套 token

> 实现说明：
> - 背景 `--surface-page / card / pop`；阴影 `--shadow-card / pop / tip`；描边 `--edge-card-* / --edge-pop-*`（含 hover 派生色）。
> - 三态 token：`--state-hover-bg`、`--shadow-press`、`--shadow-inset-soft`、`--opacity-disabled`。
> - `.card`、`WoodModal`、`WoodSelect` 下拉、`.toast`、`IconButton` 提示气泡已改用 token；
>   `inset 0 2px *` 类阴影全站收敛到 press / soft 两档；disabled 透明度统一 0.45。

**验收**：任意页面截图中，同一层级元素外观一致。

### P0-4 动效规范（状态：已完成）

- [x] 审计现有动画，统一使用 `--dur-*` 与 `--ease-*`，删除零散的 `120ms ease` 硬编码
- [x] 列表进入、弹窗、抽屉统一「淡入 + 轻微位移」，曲线保持一致
- [x] 低内存模式与 `prefers-reduced-motion` 下关闭非必要动画
- [x] 不引入 motion 库，先用 CSS 实现

> 实现说明：
> - 新增 `--dur-0: 90ms`（按下反馈），与既有 `--dur-1/2/3/4` 组成五级；全站 `transition` / `animation` 的毫秒硬编码已清零。
> - 弹窗、下拉、任务浮层统一「opacity `--dur-1` + transform `--dur-2` `--ease-out-expo`」；页面切换沿用 `--dur-3`。
> - `.low-memory` 下取消 `.reveal` / `.modal` / `.toast` / 页面切换动画，并移除按钮与卡片的位移；
>   `prefers-reduced-motion` 除压缩时长外，额外直接取消位移类动画。

**验收**：系统开启「减少动态效果」或启动器低内存模式时，无位移动画。

### P0-5 状态规范（状态：已完成）

- [x] 统一加载态：骨架屏 + 文案，替换各页面不同的「正在读取…」
- [x] 统一空状态：图标 + 标题 + 说明 + 主操作
- [x] 统一错误态：错误摘要 + 重试按钮，避免只有一行红字
- [x] 按钮 loading 统一为「动词中…」并禁用重复点击

> 实现说明：
> - 通用类：`.state` / `--card` / `--inline` / `--center`、`.state__icon/text/title/hint/actions`、`.state--error`、`.loading-block`、`.loading-rows`。
> - 已迁移：下载页版本空态与加载器错误（含真实重试）、收藏页载入、皮肤库/披风载入与错误、实例配置文件树三态、联机大厅空态、LittleSkin 两处载入。
> - 按钮「进行中…」均配合 `:disabled`，避免重复提交。

**验收**：设置、实例、下载、联机四个主页面在「空 / 载入 / 失败」三种情况下表现一致。

### P0-6 交互细节（状态：已完成）

- [x] 键盘焦点：统一 `:focus-visible` 描边，不破坏鼠标操作
- [x] 滚动条、文本选中色、禁用态透明度收敛到 token
- [x] 输入框、下拉、开关的按下反馈统一

> 实现说明：
> - 全局 `:focus-visible` 改用 `--moss` 派生色，深色主题同样可见。
> - 补上被 `outline: none` 抹掉的焦点视觉：`WoodSlider` 键盘描边、日志搜索框 `:focus-within`、配置文件编辑器描边。
> - 滚动条与 `::selection` 已在主题层统一；禁用透明度统一 `--opacity-disabled`（输入框保留 0.55 以保证内容可读）。
> - 按下反馈统一走 `--shadow-press`，与 P0-3 共用一套。

**验收**：纯键盘可完成「Tab 到控件 → 看清焦点 → 触发」；各页面禁用态与按下手感一致。

## 四、阶段 P1：能力型依赖

> 会新增体积，建议在 P0 稳定后再推进；与其他计划并行时注意体积红线，不要为了赶进度一次性全接。

### P1-1 弹层行为接管（状态：已完成）

只替换行为，不替换样式：

- [x] `WoodModal`：接入 reka-ui Dialog，获得焦点陷阱、Esc 关闭、点遮罩关闭、关闭后焦点回位
- [x] 打开弹窗时锁定页面滚动（`.modal-open .main { overflow: hidden }`，引用计数支持多层弹窗）
- [x] `WoodSelect`：键盘上下选择、Home/End、Enter 选中、Esc 关闭并回焦、首字母跳转、底部碰撞翻转
- [x] 现有 CSS 与视觉全部保留

> 实现说明与偏差：
> - **Modal 用 reka-ui Dialog**；**Select 保留自研**并补齐键盘与回焦。
> - 原因：reka-ui 的 Select 会让主 chunk 再增加约 58 KB（含 collection/popper 等），
>   Dialog 部分仅约 32 KB。Select 需要的交互用不到 100 行代码即可覆盖，因此不引入。
> - 主 chunk 581 → 616 KB（+32 KB，gzip +11 KB），在 50 KB 红线内。
> - z-index：遮罩用 `zIndex`，内容用 `zIndex + 1`，沿用原有层级约定。

**验收**：全键盘完成「打开下拉 → 选择 → 关闭」与「打开弹窗 → Esc → 焦点回位」。

### P1-2 CodeMirror 6 接入配置编辑器（状态：已完成）

- [x] 仅打开「配置文件」页并选中文件时动态加载，不影响首屏
- [x] 语言包：`.properties/.cfg/.conf/.ini`、`.toml`、`.json`；其余按纯文本
- [x] 主题全部用 CSS 变量映射当前主题，没有第二套配色
- [x] 保留 UTF-8 / GBK 读写逻辑：编辑器只处理已解码文本，保存仍按原编码写回
- [x] 低内存模式回退原生 textarea；编辑器加载失败也会自动降级为 textarea

> 实现说明：
> - 新增 `ConfigCodeEditor.vue`，由 `defineAsyncComponent` 引入；CodeMirror 相关包被拆成独立 chunk（约 4.6 KB 组件 + 若干按需 chunk）。
> - 语法高亮色板：属性名 walnut、字符串/布尔 moss、数字 amber、注释 muted。
> - `Ctrl/Cmd + S` 触发保存；切换文件用 `:key` 重建，避免语言包残留。
> - 首屏主 chunk 未增加（CodeMirror 全部在懒加载块中）。

**验收**：GTO 风格的 `config/openloader` 文件可高亮查看；GBK 文件保存后编码不变；首屏 JS 体积不增加。

### P1-3 虚拟滚动评估（状态：已评估，不引入）

- [x] 实测 500+ / 1000 条列表的渲染与滚动耗时
- [x] 结论：分页 120 条已足够流畅，**不引入** `@tanstack/vue-virtual`

> 测试方法：按实例文件行的 DOM 结构（缩略图 + 名称 + 元信息 + 两个按钮 + 开关，每行 8 个元素）
> 在 Chromium 中分别渲染 120 / 500 / 1000 条，测首屏（含两帧）耗时与 1.5 秒程序化滚动的帧间隔。

| 条数 | DOM 元素 | 首屏渲染 | 滚动平均 | P95 | 长帧（>32ms） |
| --- | --- | --- | --- | --- | --- |
| 120（当前分页） | 960 | 14.1 ms | 4.2 ms/帧 | 4.3 ms | 0 |
| 500 | 4000 | 53.6 ms | 4.2 ms/帧 | 4.3 ms | 0 |
| 1000 | 8000 | 89.6 ms | 4.2 ms/帧 | 4.3 ms | 0 |

> 分析：滚动性能在三档下几乎一致，瓶颈只在一次性挂载节点。
> 当前分页把首屏控制在 120 条（14 ms），即使某个整合包装了 1000 个 Mod 也只需一次 90 ms 的挂载，
> 且图片已 `loading="lazy"`；引入虚拟滚动会带来高度测量、搜索定位、拖拽与「显示更多」交互的额外复杂度，收益不足。
> 若未来分页上限提高或单行结构显著变重，再重新评估。

### P1-4 motion 库评估（状态：待评估）

- 先用 CSS 完成 P0-4；只有当出现「共享布局动画」「列表重排」这类 CSS 难覆盖的场景，再考虑 `motion-v`
- 默认不引入

### P1-5 图标（状态：不实施）

- 继续使用自绘 `AppIcon`，统一 stroke 风格；不换 lucide 等第三方图标库

## 六、明确不做

1. **主题对比度 / 可读性强制优化**
   - 玩家可以在玻璃透明度很低时自定义主题，也可以把字体调到很深的颜色，不再由启动器强制校验对比度。
2. **完整 UI 组件库**
   - Element Plus / Naive UI / Arco / Vuetify / PrimeVue 全量接入会覆盖现有视觉、增加 300 KB~1 MB 体积，且需要重做 12 套主题映射。
3. **替换图标体系**
4. **为美化改动业务信息架构或页面布局**

## 七、风险与对策

| 风险 | 对策 |
| --- | --- |
| reka-ui 与自绘样式冲突 | 逐组件替换，保留原 class；先做 Modal 再做 Select |
| CodeMirror 体积与低配机器 | 动态加载 + 低内存模式回退 textarea |
| 排版 token 引发全局回归 | 先在设置页试点，逐页替换，保留旧样式一个版本 |
| 动效过度 | 统一时长上限；默认关闭大幅位移；遵守 reduced-motion |
| 体积失控 | 每阶段记录构建体积，主 chunk 增幅超过 50 KB 需评审 |
